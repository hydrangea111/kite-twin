# 지상국 모니터

실제 비행 중인 연의 자세와 상태를 브라우저로 보고, 같은 조건에서 모델이
예측하는 상태와 나란히 비교하는 도구.

```
지상국 ESP32 ──USB시리얼(CSV)──> bridge.py ──SSE──> monitor.html
                                     │
                                     ├─> station/logs/*.csv   (기록)
                                     └─> export.py            (단일 HTML)
```

## 실행

```bash
python station/bridge.py --serial COM5 --sim --area 0.67
```

브라우저에서 <http://127.0.0.1:8787/>.

소스를 여러 개 주면 화면 상단 버튼으로 전환할 수 있다.

| 플래그 | 소스 |
|---|---|
| `--serial COM5` | 실측. 포트 없이 줘도 되고, 화면에서 고를 수 있다 |
| `--replay log.csv` | 기록 재생 (`--speed 2` 로 배속) |
| `--sim` | 검증된 2체 모델로 생성 |

**실측에서는 연 치수를 알려줘야 한다.**

```bash
python station/bridge.py --serial COM5 --area 0.67 --mass 0.45 --ea 3000
```

면적은 보고하는 모든 계수의 배율이다. 0.67 m² 연을 날리면서 0.50으로 역산하면
C_L이 34 % 높게 나오고, 화면에는 그걸 알려주는 것이 아무것도 없다. L/D는 비율이라
면적이 상쇄되므로 살아남는다 — 면적을 모르는 동안 믿을 수 있는 것은 L/D 쪽이다.

## 화면

| 패널 | 내용 |
|---|---|
| 디지털 트윈 (3D) | 연 위치, 처진 계류줄, 매달린 탑재물. 흐린 연은 **보정 전** 위치 |
| 분할 | 좌 실측 / 우 같은 조건에서의 모델 예측. **연동**/**개별** 로 시점을 묶거나 분리 |
| 실측 − 예측 | 고도각·장력·고도의 괴리 |
| 탑재물 자세 | 인공수평의 + YAW 나침반. pitch = 진자 흔들림 각 |
| 구조 하중 | 설계하중 대비 막대, 60초 최대 |
| 보정 | 늘어남 / 처짐각 / 측정각→현각 / 보정이 바꾼 고도 |
| 실시간 식별 | 힘 평형 역산 C_L·C_D·L/D, 장력 기준 역산 풍속 |
| 발전량 | IV 스윕 결과와 입사각 보정 |
| 센서 교정값 | 펌웨어에서 직접 읽은 상수 |

3D에서 드래그로 회전, 휠로 확대, Shift+드래그로 이동.

## 연결할 포트 고르기

상단 **포트** 버튼. 지금 보이는 시리얼 포트와, 전에 쓴 포트, 그리고 모의 리그
주소가 함께 뜬다. 직접 입력도 된다. 포트가 없거나 연결이 끊기면 3D 위에
바로 고칠 수 있는 안내가 뜬다 — 터미널로 돌아가 브리지를 다시 띄우지 않아도 된다.

USB가 빠졌다 다시 꽂히면 알아서 재접속한다.

## 기록과 재생

연결된 동안 `station/logs/` 에 **펌웨어와 같은 CSV 형식**으로 계속 쌓인다.
상단 **기록** 버튼으로 지난 비행을 골라 재생한다.

파생값이 아니라 원시 행을 적는다. 보정식을 고치면 같은 기록에서 값이 다시
계산되지만, 반대는 안 되기 때문이다. 재생은 다시 녹화하지 않는다 — 이미
있는 파일의 복사본만 쌓인다.

## 오프라인 단일 파일

```bash
python station/export.py             # 가장 최근 기록
python station/export.py --open      # 만들고 바로 열기
```

`station/export/*.html` 한 파일이 나온다. **더블클릭하면 열린다** — 파이썬도,
브리지도, 서버도, 인터넷도 필요 없다. 바람도 장비도 없는 곳에서 비행을 그대로
다시 볼 수 있다.

프레임은 파생까지 끝난 상태로 들어간다. 내보낼 때 라이브와 **같은 `Deriver`** 를
돌리므로 내보낸 화면이 현장에서 본 화면과 같다. 브라우저에서 다시 파생하면
물리 구현이 두 벌이 되고, 두 벌은 갈라진다.

`type="module"` 이 아니라 일반 스크립트로 묶는다. 크롬은 `file://` 에서 모듈
import를 막는데, 이 번들은 모듈 기능이 하나도 필요 없으므로 막힐 것 자체를
없애는 쪽을 골랐다.

## 시뮬레이터

소스를 **시뮬레이터**로 바꾸면 우측에 설정 패널이 뜬다. 풍속, 난류 강도, 돌풍,
라인 길이, 축강성 EA, 날개 면적, C_L·C_D, 탑재물 질량, 목줄 길이, 경계층 적용
여부를 바꾸고 **적용 · 재적분**. 처음 보는 조합은 30초쯤 걸리고, 그 뒤로는
캐시에서 즉시 나온다.

설정은 `.station-state.json` 에 남으므로 브리지를 다시 띄워도 유지된다.
분할 여부와 시점은 브라우저에 남는다.

## 설계상 주의한 것

**식별은 준정적 구간에서만 갱신한다.** 한 샘플을 그대로 역산하면 과도구간에서
C_D가 2배로 나온다 — 잡음이 아니라 전제가 깨진 것이다. `sim/twin.py` 와 같은
문턱값(0.8 N/s, 1.5°/s)으로 걸러 통과한 표본만 중앙값에 넣는다. 변화율은
인접 샘플이 아니라 창 전체에 대해 잰다(인접 차분은 센서 잡음만 측정한다).

**처짐 보정은 20°에서 자른다.** δ ∝ 1/T 라 줄이 늘어지면 발산한다 —
T=0.01 N에서 1151°가 나온다. `model.sag_angle` 이 "20°를 넘으면 범위 밖"이라고
직접 적어둔 한계이고, 지키지 않았을 때 화면에 고도각 98°가 떴다. 이 연의
L/D로는 63°가 상한이라 불가능한 값이다. 자른 값은 "범위 밖"으로 표시하고,
슬랙 구간 표본은 식별에 넣지 않는다.

**역산 풍속은 중력항을 포함한 평형식을 푼다.** `T = q·√(C_L²+C_D²)` 로 줄이면
양력이 자중을 먼저 들어야 한다는 사실이 빠져 모든 풍속에서 낮게 읽히고,
약풍에서 가장 심하다 — 하필 이 교차검증이 가장 쓸모 있는 구간이다.

**고도각이 2° 아래면 그리지 않는다.** 그 아래에서는 양력 방향 가정 자체가
실제 연을 서술하지 않으므로, 땅 밑에 연을 그리는 대신 "비행 중 아님"을 띄운다.

**방위각은 측정값이 아니다.** 지상국에 방위 센서가 없어 탑재물 yaw를 비행면
방위로 쓴다. 화면에 그렇게 적어두었고, 지면의 반투명 부채꼴이 그 불확실성이다.
2축 각도센서를 달면 가정에서 측정으로 바뀐다.

**모의 데이터는 실측처럼 보이지 않게 한다.** `socket://` 주소는 가짜 리그이지
ESP32가 아니므로, 경로가 같아도 배지에 "실측"이라고 쓰지 않는다. 보고 있는
것을 과장하는 모니터는 없느니만 못하다.

## 하드웨어 없이 전 구간 시험

`fake_rig.py` 는 `firmware/ground/src/main.cpp` 가 찍는 것과 똑같은 바이트를
TCP로 내보낸다. pyserial이 이걸 진짜 시리얼 포트로 취급하므로, 시리얼 경로를
우회하는 게 아니라 그대로 통과한다.

```bash
python station/fake_rig.py                                    # 터미널 1
python station/bridge.py --serial socket://127.0.0.1:5577 --sim --area 0.67
```

내보내는 숫자는 2체 모델의 것이다. 그럴듯한 잡음을 지어냈다면, 통과해도
물리에 대해 아무것도 증명하지 못한다.

UI의 이상 상태를 확인할 때:

```bash
--drop 0.05     행 5 % 유실 (약한 무선 링크)
--garbage 0.02  가끔 깨진 행
--stall 20      20초 뒤 송신 중단 ("신호 끊김" 표시 확인)
```

## 펌웨어와의 접합부

여기엔 스키마도 핸드셰이크도 없다. ESP32가 한 줄 찍고, 브리지가 쉼표로 쪼갠다.
어긋나도 예외가 나지 않는다 — 데이터가 아예 안 들어오거나, 더 나쁘게는
**엉뚱한 열에 들어온다.**

실제로 한 번 일어났다. printf의 형식 지정자가 27개인데 인자가 28개여서
8번 열(`uptime_ms`)부터 전부 한 칸씩 밀렸고, `yaw`(float)가 `%u`로,
`sats`(uint8)가 `%.7f`로 찍히고, `pv_valid`는 출력되지 않았다. 결과는 27열짜리
줄이고, 브리지는 28열을 요구하므로 **모든 줄을 거부했을 것이다.**
눈으로는 안 보였고 기계적으로 세고 나서야 드러났다. 그래서 세는 것이 테스트다.

```bash
python -m pytest station/test_bridge.py -q
```

`test_bridge.py` 는 `main.cpp` 를 직접 파싱해서 지정자 수 = 인자 수 = 헤더 열 수
= `len(COLUMNS)` 를 확인하고, 지정자 타입이 인자 타입과 맞는지도 본다
(float을 `%u` 로 넘기는 것은 C에서 미정의 동작이라 ESP32에서는 실패가 아니라
쓰레기값이 찍힌다). 펌웨어를 고치면 이 테스트가 같이 움직인다.

검사가 실제로 그 버그를 잡는지도 확인했다 — printf를 원래대로 되돌리면
24개 중 19개가 실패한다.
